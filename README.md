## مرور کلی

T2HASH یک **رله تونل UDP در لایه صفر** است که به طور کامل با اسمبلی x64 NASM نوشته شده. این پروژه با دور زدن سربار پشته TCP/IP کرنل — که راه‌حل‌های تونلینگ مبتنی بر زبان‌های سطح بالا را آزار می‌دهد — مستقیماً با syscallهای لینوکس ارتباط برقرار می‌کند. نتیجه: تأخیر زیر ۱۰۰ میکروثانیه و توان عملیاتی نزدیک به سرعت خط.

**این پروژه چه مشکلی را حل می‌کند؟** ابزارهای تونلینگ مدرن (V2Ray، WireGuard، OpenVPN) با Go، Rust یا C++ ساخته می‌شوند. این زبان‌ها سه گلوگاه اجتناب‌ناپذیر ایجاد می‌کنند:

| ضعف | تأثیر |
|---|---|
| **مکث‌های Garbage Collector** | رویدادهای STW غیرقابل پیش‌بینی در Go/Java — جهش jitter تا ۵۰ میلی‌ثانیه |
| **تعویض زمینه (Context Switching)** | جابه‌جایی‌های مکرر بین user-mode و kernel-mode حدود ۳۰٪ از چرخه‌های CPU را هدر می‌دهد |
| **سربار لایه کاربردی** | عبور از پشته TCP/IP کرنل بیش از ۱۵ میکروثانیه تأخیر به هر بسته اضافه می‌کند |

در شبکه‌هایی که سیستم‌های DPI ترافیک را با دقت نانوثانیه تحلیل می‌کنند، این تأخیرها نه تنها عملکرد را کاهش می‌دهند — بلکه **امضای زمانی** ایجاد می‌کنند که ترافیک را قابل شناسایی می‌سازد. T2HASH هر سه گلوگاه را با اجرای مستقیم در سطح syscall حذف می‌کند.

## ویژگی‌ها

### موتور هسته
- **اسمبلی خالص x64 (NASM)** — بدون runtime، بدون garbage collector، بدون تعویض زمینه
- **رابط مستقیم syscall** — توابع `socket()`، `bind()`، `recvfrom()`، `sendto()` مستقیماً از Ring 0 فراخوانی می‌شوند
- **جهش در سطح رجیسترهای CPU** — تبدیل بسته‌ها در سیلیکون رخ می‌دهد، نه در حافظه heap
- **باینری زیر ۱۰ کیلوبایت** — بدون وابستگی، بدون سطح حمله لینک پویا، stripped و مبهم‌سازی شده
- **حلقه رویداد تک‌رشته‌ای** — عملکرد قابل پیش‌بینی و اندازه‌گیری در هر بار

### نسخه 3.0: انتقال مقاوم در برابر DPI (جدید)
- **۸ ماسک XOR چرخشی** — چرخش ماسک مبتنی بر شمارنده بسته، تحلیل امضای استاتیک را حذف می‌کند
- **پدینگ تصادفی بسته (۱ تا ۲۵۶ بایت)** — طول متغیر پدینگ برای هر بسته، قابل تنظیم با پروفایل
- **jitter میکروثانیه‌ای** — تأخیر تصادفی بین بسته‌ای، همبستگی زمانی را خنثی می‌کند
- **هدر حالت برای هر بسته** — شناساگر ۱ بایتی از بازگشت خودکار به حالت Legacy پشتیبانی می‌کند
- **پروفایل‌های انتقال قابل تنظیم** — پیش‌فرض‌های Balanced، Aggressive یا Stealth
- **زنجیره بازگشت خودکار** — دیمن ناظر سلامت رله DPI را بررسی کرده و در صورت خرابی، Legacy را فعال می‌کند

### استتار و ضد-DPI
- **بدون امضای پروتکل** — بدون TLS handshake، بدون هدر HTTP، بدون بنر SSH، بدون شروع WireGuard
- **ترافیک به صورت نویز تصادفی UDP ظاهر می‌شود** — جهش XOR با ماسک‌های ۶۴ بیتی توزیع آنتروپی یکنواخت تولید می‌کند
- **استتار پورت ۴۴۳** — با ترافیک QUIC/HTTP3 ترکیب می‌شود، رایج‌ترین UDP در اینترنت
- **انتقال بدون حالت (UDP)** — بدون handshake نشست برای اثرانگشت‌گیری DPI، بدون ماشین حالت برای ردیابی

### عملیاتی
- **استقرار تک‌خطی** — یک دستور همه چیز را روی هر دو نوع سرور نصب می‌کند
- **یکپارچگی با systemd** — راه‌اندازی خودکار، راه‌اندازی مجدد در صورت خرابی، لاگ‌گیری journald
- **پورت‌های قابل تنظیم** — تمام پورت‌های شنود در زمان نصب قابل تغییر
- **بازنویسی با متغیرهای محیطی** — هر تنظیم از طریق env varهای `T2HASH_*` قابل کنترل است
- **تنظیم پایدار کرنل** — بهینه‌سازی بافر در `/etc/sysctl.conf` نوشته می‌شود

### نقشه پورت‌ها

| مکان | سرویس | پورت پیش‌فرض | پروتکل | هدف |
|---|---|---|---|---|
| ایران | SOCKS5 | `8080` | TCP | نقطه ورود کلاینت |
| ایران | Gost KCP (محلی) | `127.0.0.1:7777` | UDP/KCP | رله داخلی به ASM |
| ایران | `asm_udp_ir` / `asm_udp_ir_dpi` | `0.0.0.0:7777` | UDP | جهش و ارسال به خارج |
| خارج | `asm_udp_hz` / `asm_udp_hz_dpi` | `0.0.0.0:443` | UDP | دریافت، رمزگشایی، ارسال |
| خارج | Gost KCP (محلی) | `127.0.0.1:1080` | UDP/KCP | خروج به اینترنت |

## نصب

### پیش‌نیازها

| نیازمندی | جزئیات |
|---|---|
| **سیستم‌عامل** | اوبونتو 20.04+ یا دبیان 11+ (x86_64) |
| **دسترسی** | `root` — اسکریپت با کرنل و systemd تعامل دارد |
| **سرور خارج** | یک VPS با پهنای باند کافی (Hetzner، OVH و غیره) |
| **سرور ایران** | یک سرور با دسترسی root |
| **فایروال** | پورت `443/UDP` باید روی VPS خارج باز باشد |

> نصب‌کننده پارامترهای کرنل و فایل‌های سرویس systemd را تغییر می‌دهد. اجرا روی یک سرور تازه نصب شده توصیه می‌شود.

### نصب سریع (تک‌خطی)

این دستور را روی **هر دو** سرور (ایران و خارج) اجرا کنید:

```bash
curl -Ls -o t2hash-deploy https://raw.githubusercontent.com/T2HASH/T2HASH-CORE/main/t2hash-deploy && chmod +x t2hash-deploy && ./t2hash-deploy
```

نصب‌کننده از شما خواهد پرسید:
1. **نوع سرور** — `1` برای خارج (دریافت‌کننده)، `2` برای ایران (فرستنده)
2. **IP خارج** — (فقط ایران) آدرس IP سرور خارج شما
3. **حالت انتقال** — `1` Legacy، `2` DPI-Safe، یا `3` Hybrid
4. **پروفایل انتقال** — (فقط DPI-Safe/Hybrid) `1` Balanced، `2` Aggressive، `3` Stealth

### بازنویسی با متغیرهای محیطی

تمام تنظیمات از طریق متغیرهای محیطی **قبل از** اجرای نصب‌کننده قابل شخصی‌سازی هستند:

```bash
# مثال: نصب با پروفایل تهاجمی و پورت‌های سفارشی
export T2HASH_HZ_PORT=8443
export T2HASH_IR_PORT=8888
export T2HASH_SOCKS_PORT=1080
export T2HASH_PAD_MIN=64
export T2HASH_PAD_MAX=256
export T2HASH_JITTER_MAX_US=2000
export T2HASH_FALLBACK_TIMEOUT=10
./t2hash-deploy
```

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `T2HASH_BUF_SIZE` | `26214400` | اندازه بافر سوکت (بایت) |
| `T2HASH_IR_PORT` | `7777` | پورت شنود سمت ایران |
| `T2HASH_HZ_PORT` | `443` | پورت شنود سمت خارج |
| `T2HASH_GOST_PORT` | `1080` | پورت داخلی Gost KCP |
| `T2HASH_SOCKS_PORT` | `8080` | پورت پروکسی SOCKS5 |
| `T2HASH_GOST_VERSION` | `2.11.5` | نسخه باینری Gost |
| `T2HASH_MTU` | `1350` | اندازه MTU پروتکل KCP |
| `T2HASH_KCP_MODE` | `normal` | حالت عملکرد KCP |
| `T2HASH_PAD_MIN` | `1` | حداقل بایت‌های پدینگ |
| `T2HASH_PAD_MAX` | `128` | حداکثر بایت‌های پدینگ |
| `T2HASH_JITTER_MAX_US` | `500` | حداکثر jitter به میکروثانیه |
| `T2HASH_FALLBACK_TIMEOUT` | `15` | ثانیه قبل از فعال‌سازی بازگشت |
| `T2HASH_LOG_LEVEL` | `info` | سطح جزئیات لاگ |

### مدیریت سرویس‌ها

```bash
# بررسی وضعیت
systemctl status asm-hz gost-hz        # خارج
systemctl status asm-ir gost-ir        # ایران

# سرویس‌های حالت DPI (نسخه 3.0)
systemctl status asm-hz-dpi            # رله DPI خارج
systemctl status asm-ir-dpi            # رله DPI ایران
systemctl status t2hash-fallback       # ناظر بازگشت (فقط Hybrid)

# راه‌اندازی مجدد
systemctl restart asm-hz gost-hz
systemctl restart asm-ir gost-ir

# مشاهده لاگ‌ها
journalctl -u asm-hz-dpi -f            # لاگ‌های حالت DPI
journalctl -u asm-hz -f                # لاگ‌های حالت Legacy
journalctl -u t2hash-fallback -f       # لاگ‌های ناظر

# توقف و غیرفعال‌سازی
systemctl stop asm-hz gost-hz
systemctl disable asm-hz gost-hz
```

## پیکربندی

### فایل پیکربندی

پس از نصب، تنظیمات در `/etc/t2hash/t2hash.conf` ذخیره می‌شود:

```ini
# پیکربندی T2HASH نسخه 3.0
server_type=1
transport_mode=3
transport_profile=balanced
hz_port=443
ir_port=7777
gost_port=1080
socks_port=8080
buf_size=26214400
pad_min=1
pad_max=128
jitter_max_us=500
fallback_timeout=15
gost_version=2.11.5
mtu=1350
kcp_mode=normal
```

این فایل صرفاً برای **مرجع** است — رفتار زمان اجرا در زمان نصب/کامپایل تعیین می‌شود. برای تغییر تنظیمات، نصب‌کننده را دوباره اجرا کنید.

### پیکربندی پورت سفارشی

پورت‌ها را می‌توان در زمان نصب بدون متغیرهای محیطی تنظیم کرد — نصب‌کننده اکنون برای هر پورت درخواست می‌کند:

```
Port ha (Enter = pishfarz):

Port daryaft (HZ) [pishfarz: 443]:
Port daryaft (IR) [pishfarz: 7777]:
Port SOCKS5 [pishfarz: 8080]:
```

## حالت‌های انتقال

T2HASH نسخه 3.0 سه حالت انتقال را معرفی می‌کند. در زمان نصب انتخاب کنید.

### حالت ۱: Legacy (سازگار با نسخه 2.0)

انتقال اصلی XOR با ماسک تکی. از یک ماسک استاتیک `0x5A` روی تمام بسته‌ها استفاده می‌کند.

- **سازگاری**: کاملاً با نصب‌های نسخه 2.0 interoperable است
- **سربار**: صفر — بدون بایت حالت، بدون پدینگ، بدون jitter
- **مقاومت DPI**: کم — امضای XOR استاتیک به راحتی قابل بازگشت است
- **مناسب برای**: استقرارهای موجود، محیط‌هایی که DPI در آن‌ها تهاجمی نیست

**فرمت بسته:** `[payload_XOR_شده]`

### حالت ۲: DPI-Safe (جدید)

XOR چرخشی چندماسکه با پدینگ و jitter. هشت ماسک ۶۴ بیتی متمایز برای هر بسته می‌چرخند. پدینگ تصادفی بین ۱ تا ۲۵۶ بایت (وابسته به پروفایل). تأخیر بین بسته‌ای ۰ تا ۲۰۰۰ میکروثانیه.

- **مقاومت DPI**: بالا — بدون امضای استاتیک، اندازه بسته‌های متغیر، نویز زمانی
- **سربار**: ۲+ بایت برای هر بسته (بایت حالت + طول پدینگ)، به اضافه بایت‌های پدینگ و تأخیر jitter
- **سازگاری**: نیاز به هر دو طرف با نسخه 3.0 و ماسک‌های یکسان
- **مناسب برای**: شبکه‌های محدودکننده با DPI فعال، ترافیک با ارزش بالا

**فرمت بسته:** `[0x01][payload_XOR_شده][طول_پدینگ][بایت‌های_پدینگ]`

### حالت ۳: Hybrid (توصیه شده)

رله DPI-Safe را به عنوان اصلی با یک ناظر بازگشت خودکار اجرا می‌کند. اگر رله DPI خراب شود (crash، تداخل پورت، اتمام منابع)، یک دیمن پس‌زمینه قطعی را تشخیص داده و رله Legacy را فعال می‌کند. وقتی DPI بازیابی شود، Legacy متوقف و DPI از سر گرفته می‌شود.

- **مقاومت DPI**: بالا (اصلی)، به طور ملایم به متوسط کاهش می‌یابد (بازگشت)
- **قابلیت اطمینان**: بالاترین — بدون نقطه شکست تکی
- **سربار**: هر دو باینری کامپایل می‌شوند، ناظر CPU ناچیزی مصرف می‌کند
- **مناسب برای**: استقرارهای تولیدی، زیرساخت حیاتی، هر راه‌اندازی که uptime در آن مهم است

**رفتار بازگشت:**
```
رله DPI فعال    ──► Legacy متوقف، DPI فعال
رله DPI غیرفعال ──► پس از ۱۵ ثانیه (قابل تنظیم): شروع Legacy
رله DPI فعال    ──► توقف Legacy، از سرگیری DPI
```

### پروفایل‌های انتقال

هنگام استفاده از حالت DPI-Safe یا Hybrid، یک پروفایل انتخاب کنید:

| پروفایل | محدوده پدینگ | محدوده Jitter | توان عملیاتی | استتار |
|---|---|---|---|---|
| **Balanced** (پیش‌فرض) | ۱-۱۲۸ بایت | ۰-۵۰۰ میکروثانیه | بالا | خوب |
| **Aggressive** | ۶۴-۲۵۶ بایت | ۰-۲۰۰۰ میکروثانیه | متوسط | حداکثر |
| **Stealth** | ۱-۶۴ بایت | ۰-۲۵۰ میکروثانیه | حداکثر | متوسط |

## عیب‌یابی

### مشکلات رایج

| علامت | علت احتمالی | راه حل |
|---|---|---|
| `asm-hz` یا `asm-hz-dpi` خراب | پورت در حال استفاده | `ss -ulnp \| grep <port>` — پروسه متعارض را kill کنید |
| `gost-hz` خراب | باینری خراب | `rm /usr/local/bin/gost` و نصب مجدد |
| عدم اتصال | فایروال UDP را مسدود کرده | `ufw allow <port>/udp` روی سرور خارج |
| افت بسته بالا | بافر کرنل خیلی کوچک | بررسی `sysctl net.core.rmem_max` = ۲۶,۲۱۴,۴۰۰ |
| سرعت پایین | عدم تطابق MTU پروتکل KCP | تنظیم MTU در فایل سرویس gost (پیش‌فرض ۱۳۵۰) |
| بازگشت فعال نمی‌شود | ناظر نصب نشده | فقط در حالت Hybrid (حالت ۳) در دسترس است |
| رله DPI شروع نمی‌شود | NASM موجود نیست | `apt-get install nasm build-essential` |

### دستورات مانیتورینگ

```bash
# بررسی شنود UDP
ss -ulnp | grep -E '7777|443'

# بررسی مصرف CPU (باید نزدیک صفر باشد)
top -p $(pgrep asm_udp)

# بررسی افت بسته کرنل
cat /proc/net/udp

# تست پهنای باند (روی خارج اجرا شود)
iperf3 -s -p 5201
# از ایران:
iperf3 -c <IP_KHAREJ> -p 5201 -u -b 100M

# مشاهده تصمیمات ناظر بازگشت
journalctl -u t2hash-fallback -f

# تأیید حالت انتقال از لاگ‌ها
journalctl -u asm-hz-dpi --since "5 min ago" | grep "relay"
```

### تأیید حالت انتقال شما

```bash
# بررسی اینکه کدام سرویس‌های ASM فعال هستند
systemctl is-active asm-hz       # رله Legacy (فعال = حالت نسخه 2.0 یا بازگشت)
systemctl is-active asm-hz-dpi   # رله DPI (فعال = حالت DPI نسخه 3.0 یا Hybrid)

# بررسی پیکربندی
cat /etc/t2hash/t2hash.conf | grep transport_mode
# 1 = Legacy، 2 = DPI-Safe، 3 = Hybrid
```

## نکات ایمنی و قانونی

### موارد استفاده

T2HASH به عنوان یک ابزار مهندسی شبکه برای موارد زیر طراحی شده است:
- دور زدن سانسور اینترنت در مناطقی که دسترسی به اطلاعات محدود است
- تحقیق و تست فناوری‌های فیلترینگ شبکه
- اهداف آموزشی در شبکه‌های کامپیوتری و برنامه‌نویسی اسمبلی
- بهبود قابلیت اطمینان اتصال در شبکه‌هایی با شکل‌دهی ترافیک تهاجمی

### ملاحظات مهم

- **T2HASH فقط ابهام‌سازی (obfuscation) ارائه می‌دهد، نه رمزنگاری.** لایه جهش XOR ترافیک را برای بازرسی سطحی غیرقابل خواندن می‌کند اما امنیت رمزنگاری فراهم نمی‌کند. برای محرمانگی محتوا از رمزنگاری لایه کاربردی (TLS، SSH) استفاده کنید.
- **بدون احراز هویت.** هر کسی که پورت را بداند می‌تواند بسته ارسال کند. در استقرارهای عمومی، قوانین فایروال را به IPهای مورد اعتماد محدود کنید.
- **انطباق قانونی.** قانونی بودن ابزارهای دور زدن در حوزه‌های قضایی مختلف متفاوت است. کاربران مسئول درک و رعایت قوانین محلی هستند.
- **بدون جمع‌آوری داده.** T2HASH هیچ داده‌ای جمع‌آوری نمی‌کند، چیزی فراتر از آنچه systemd به طور پیش‌فرض ثبت می‌کند لاگ نمی‌کند و هیچ اتصال خارجی فراتر از رله‌های پیکربندی شده برقرار نمی‌کند.
- **طراحی تک‌رشته‌ای.** هر باینری اسمبلی یک حلقه رویداد را مدیریت می‌کند. برای مقیاس‌پذیری چند هسته‌ای، چند نمونه با `SO_REUSEPORT` مستقر کنید.

### مدل امنیتی

```
┌─────────────────────────────────────────┐
│  لایه کاربردی (TLS/SSH)       ← رمزنگاری │
├─────────────────────────────────────────┤
│  لایه Gost KCP                 ← قابلیت اطمینان │
├─────────────────────────────────────────┤
│  لایه اسمبلی T2HASH            ← ابهام‌سازی │
├─────────────────────────────────────────┤
│  لایه UDP / IP                 ← مسیریابی │
└─────────────────────────────────────────┘
```

T2HASH در لایه ابهام‌سازی عمل می‌کند. این یک جزء از استراتژی دفاع در عمق است، نه یک راه‌حل امنیتی کامل.

## تغییرات

### نسخه 3.0.0 (فعلی)

**ویژگی‌های جدید:**
- حالت انتقال مقاوم در برابر DPI با ۸ ماسک XOR چرخشی
- پدینگ تصادفی بسته (۱ تا ۲۵۶ بایت، محدوده قابل تنظیم)
- jitter میکروثانیه‌ای بین بسته‌ای (۰ تا ۲۰۰۰ میکروثانیه، قابل تنظیم)
- پروفایل‌های انتقال قابل تنظیم: Balanced، Aggressive، Stealth
- حالت Hybrid با بازگشت خودکار به انتقال Legacy
- دیمن ناظر بازگشت با پایش سلامت
- هدر حالت برای هر بسته جهت مذاکره پروتکل
- پورت‌های قابل تنظیم در زمان نصب (IR، HZ، SOCKS5)
- فایل پیکربندی مرجع `/etc/t2hash/t2hash.conf`
- بازنویسی تنظیمات با متغیرهای محیطی (`T2HASH_*`)
- یکپارچگی journald در systemd با لاگ‌گیری ساختاریافته
- فایل‌های `.asm` مستقل برای کامپایل دستی

**بهبودها:**
- پیکربندی پورت اکنون در زمان ساخت به hex تبدیل می‌شود (بدون مقادیر hardcoded)
- تمام اندازه‌های بافر سوکت از طریق `T2HASH_BUF_SIZE` قابل تنظیم
- نسخه Gost از طریق `T2HASH_GOST_VERSION` قابل انتخاب
- MTU و حالت KCP از طریق متغیرهای محیطی قابل تنظیم
- پاک‌سازی اکنون تمام نسخه‌ها (Legacy + DPI) را هنگام نصب مجدد حذف می‌کند
- مدیریت خطا: توقف در صورت شکست کامپایل/لینک با پیام‌های مشخص

### نسخه 2.0

- انتشار عمومی اولیه
- رله UDP اسمبلی خالص x64 NASM
- ابهام‌سازی XOR با ماسک تکی استاتیک (0x5A)
- پشتیبانی از SO_REUSEADDR
- تنظیم بافر کرنل ۲۵ مگابایت
- یکپارچگی سرویس systemd
- اسکریپت استقرار تک‌خطی
- معماری دو گره‌ای (IR/HZ)

## مراحل تست دستی

برای تأیید نصب نسخه 3.0:

1. **تأیید کامپایل باینری:**
   ```bash
   file /root/asm_udp_hz_dpi   # باید نشان دهد "ELF 64-bit LSB executable"
   file /root/asm_udp_ir_dpi   # باید نشان دهد "ELF 64-bit LSB executable"
   ```

2. **تأیید راه‌اندازی سرویس:**
   ```bash
   systemctl status asm-hz-dpi   # باید "active (running)" نشان دهد
   systemctl status gost-hz      # باید "active (running)" نشان دهد
   ```

3. **بررسی حالت انتقال در لاگ‌ها:**
   ```bash
   journalctl -u asm-hz-dpi --since "1 min ago" | grep "relay bound"
   # باید نشان دهد: [T2HASH-DPI] HZ relay (profile=balanced) bound on port 443
   ```

4. **تست بازگشت (فقط حالت Hybrid):**
   ```bash
   # kill کردن رله DPI
   systemctl stop asm-hz-dpi
   # ۱۵ ثانیه صبر کنید، سپس بررسی کنید
   journalctl -u t2hash-fallback --since "1 min ago"
   # باید نشان دهد: [T2HASH-FALLBACK] Activating legacy fallback!
   systemctl status asm-hz   # اکنون باید فعال باشد
   # راه‌اندازی مجدد رله DPI
   systemctl start asm-hz-dpi
   # پس از چند ثانیه، Legacy باید به طور خودکار متوقف شود
   ```

5. **تأیید جریان بسته:**
   ```bash
   # روی خارج
   ss -ulnp | grep 443   # باید asm_udp_hz_dpi در حال شنود نشان دهد
   # روی ایران
   ss -ulnp | grep 7777  # باید asm_udp_ir_dpi در حال شنود نشان دهد
   ```

6. **سازگاری با نسخه قبلی Legacy:**
   ```bash
   # یک سمت را با حالت ۱ (Legacy) و سمت دیگر را با حالت ۳ (Hybrid) نصب کنید
   # سمت Legacy بایت حالت 0x00 دریافت می‌کند، سمت DPI به handler Legacy هدایت می‌شود
   journalctl -u asm-hz-dpi --since "1 min ago" | grep "legacy"
   # باید نشان دهد: [T2HASH-DPI] HZ fallback: legacy packet received
   ```
